# C++ 原生计算核心重迁方案（与 TS 逐位一致）

## 目标

在 `electron/native/` 重建 C++ 计算核心，对任意计算请求输出与 TS 管线**逐位相同**的结果（相同御魂 ID 序列、相同顺序、相同 score），替换上次失败的穷举式实现。混合架构：TS 紧凑快路径与种子生成留在 TS 单份维护，C++ 只接管真正慢的两条束搜索。性能验收基准：一万多御魂 + 多约束的普通模式。

## 架构设计

### 分派流程（复用上次已验证的进程骨架）

```
UI hook (useRelicCalculation)
  └→ payload worker (恢复 nativeCalculatorPayload.worker.ts，重写内容)
       ├─ 镜像 calculateRelicCombinations 的分支树做 TS 侧分派：
       │   ├─ 紧凑引擎可用（engine 1/2 及其早退分支）→ 直接在 worker 内用 TS 算完返回（这些本来就是快路径）
       │   └─ 否则（束搜索形态）→ 用 TS 紧凑引擎算出 top-1 种子，序列化协议文本返回
  └→ window.desktop.calculateRelicsNative(bytes)  (preload IPC)
       └→ electron/main.ts spawn build/native/relic-calculator.exe，stdin 写协议、stdout 收结果
  └→ hydrate：按全局索引还原 RelicView，用标准 calculateRelicPanel 重建面板，走原有 merge/prioritize 逻辑
```

- 失败/超时/空结果 → 无声回退现有 TS 多 Worker 路径（保留现有兜底机制）。
- 4+0 两阶段流程保持现有 round 结构：两次原生调用（unrestricted / explicit），协议携带 phase。
- 修复上次遗留缺陷：main.ts 里每请求独立进程句柄（可单独取消），不再用全局单句柄。

### 协议 v2（文本、stdin/stdout，沿用 YYS_NATIVE_1 风格）

序列化原则：**一切字符串/正则/localeCompare 语义留在 TS**，C++ 只收索引和 double。

新增/调整字段：
- `fixedSuitPhase`（unrestricted/explicit）、`fixedPatternIndexes`（布局子集或全部）
- 折算后的基础面板 + buffPercents（TS 先跑 applyExtraAttributes）
- 每位置**已过资格过滤**的御魂（全局索引、套装索引、是否可触发两件套、11 维 StatVector）——沿用上次 `relicStatVectorFor` 的切点，逐位求和顺序由 TS 固定
- 套装表：两件套加成 11 维向量 + 每个 requiredTwoPieceAttribute 对应的**精确文本匹配**套装索引集（修复上次语义偏差 #1）
- 4+2-属性展开的有序套装名列表（TS 预排序，避免 localeCompare 进 C++）
- 种子结果（6 个全局索引 + score + criticalRateOverflow）
- double 序列化统一 `%.17g` 保证往返无损（Phase 0 内先用往返测试验证）
- 输出：RESULT 行（score、6 索引、criticalRateOverflow）；进度走 stderr 粗粒度阶段行 → main.ts 转 IPC

### C++ 模块布局（与 TS 文件一一对应，便于逐行对照评审）

```
electron/native/

  panel.cpp/.h                // calculatePanelFromStats / calculatePanelMetric / satisfiesPanelRange（对齐 calculator/panel.ts 运算顺序）
  ranking.cpp/.h              // prioritizeCalculatorResults 等价（score desc || critOverflow asc、按排序后 id 去重、slice）
  candidates.cpp/.h           // localScore、稳定排序、generalCandidateFrontier 拼接顺序、candidateBudget
  constraints.cpp/.h          // constraintsForSearch / requirementSignature / panelConstraintProgress / 分桶签名
  bounds.cpp/.h               // suffix maxima、optimistic stats、cannotBeatFastResult、potentialFixedSuitTwoPieceStats
  general-beam.cpp/.h         // 镜像 calculator/generalBeamSearch.ts（engine 4）
  fixed-suit-layout.cpp/.h    // 镜像 calculator/fixedSuitLayoutSearch.ts（engine 3，最大模块）
  fixed-suit-support.cpp/.h   // 镜像 expansion/retention/state/plan/fixedCandidates
  protocol.cpp/.h             // 解析/输出
  main.cpp                    // --compute / --self-check / --trace
  build.ps1                   // 恢复上次脚本：cl /std:c++20 /O2 /W4 /WX /utf-8，明确不加 /fp:fast、不开 FMA 收缩（保证 IEEE 逐位一致）
```

### 逐位一致的确定性规则清单（实现时逐条对照）

- JS 稳定排序 → `std::stable_sort`；Map/Set 插入序 → 只用 vector + 追加去重，禁用 unordered_map 参与任何有序逻辑
- 平局裁决：takeBest/offerBest 的 `{value, index}` 索引平局规则原样移植
- `Math.floor(x + Number.EPSILON)` → `std::floor(x + DBL_EPSILON)`；PARETO_EPSILON=1e-9 等常量逐个对齐
- 求和顺序：逐御魂向量 TS 侧已定型，跨位置累加按位置顺序，禁止编译器重排（precise 模式下 +,-,*,/ 不重结合）
- 比较器里 `Math.abs(delta) > Number.EPSILON` 门控原样保留

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| JS/C++ 浮点不一致 | precise 模式 + 相同运算顺序 + %.17g 往返；Phase 0 先验证 |
| 隐性顺序语义（Map 迭代序、localeCompare） | 字符串语义全部 TS 预解析成索引；C++ 禁用哈希容器参与有序逻辑 |
| 未来 TS 算法改动导致两份代码漂移 | 差分测试进 test:native-calculator，任何漂移立刻红灯 |
| 大账号 payload 体积 | 只传已过滤候选，1 万御魂约 1-2MB，低于 8MB 上限 |
| 平局跨 Worker 合并顺序 | 差分契约按单请求定义；C++ 内部按布局序确定性合并 |
